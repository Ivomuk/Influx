qa_vw1_credit_v1_duplicate_fid.txt			QA on vw1				Detects duplicate financial_id records
qa_vw1_credit_v1_invalid_subscriber_msisdn.txt		QA on vw1				Flags null or malformed MSISDNs

qa_vw1_credit_v1_signed_amount_sanity.txt		QA on vw1				Validates signed amounts are directionally correct
vw2_credit_v1_subscriber_day.txt			Layer 1 — daily rollup			Aggregates vw1 events to one row per subscriber per day
qa_vw2_credit_v1_subscriber_day.txt			QA on vw2				6 SQL checks: duplicates, negative amounts, count integrity, binary flags, disbursement/amount consistency, future dates
vw3_credit_v1_layer1_features.txt			Layer 1 — feature engineering		Builds 7d/14d/30d/60d/90d windows, anti-gaming flags, identity maturity signals
qa_vw3_credit_v1_layer1_features.txt			QA on vw3				8 SQL checks: repayment ratio range, anti-gaming flag integrity, negative exposure, active-days bounds, SIM age, sim_age_cohort values, identity score range, duplicates
vw4_credit_v1_layer0_scores.txt				Layer 0 — scoring			Converts Layer 1 features into 10 deterministic scores: expected_repayment_probability, expected_credit_loss_rate, churn_cooling_probability, expected_future_transaction_margin_score, expected_treatment_cost_score, customer_lifetime_value_contribution (derived), debt_stress_index_v1, fraud_abuse_risk_score, behavior_consistency_score, identity_confidence_score
qa_vw4_credit_v1_layer0_scores.txt			QA on vw4				7 SQL checks: all 10 scores in valid range, DSI in [0,100], null scores, CLV formula sanity, anti-gaming flag pass-through integrity, duplicates, vw3→vw4 join coverage
vw5_credit_v1_reason_codes.txt				Layer 3 — SQL reason codes		Per-subscriber primary_reason_code computed in SQL. Consumed by the Python decision engine as the authoritative source for primary_policy_reason (overrides Python np.select)
vw6_credit_v1_cap_and_action.txt			Layer 3 — SQL conservative cap		Per-subscriber conservative_credit_limit_v1 and recommended_action computed in SQL. Consumed by select_final_capacity_output as a hard per-subscriber ceiling below policy_capacity_cap

File					Layer			What it does
Config.txt				Config for Layers 2–4	All thresholds, caps, stability bounds, budget settings, anti-gaming switches for the decision engine
run_credit_v1_decision_engine.txt	Layers 2–4		build_policy_prefilter(vw5_reason_codes_df) overrides primary_policy_reason with SQL-authoritative vw5 value. select_final_capacity_output(vw6_cap_action_df) applies conservative_credit_limit_v1 as hard per-subscriber ceiling. run_credit_v1_decision_engine(circuit_breaker_multiplier) scales policy_capacity_cap by the portfolio feedback multiplier before TNV evaluation. Real-Time Eligibility API

Lender API call  ──▶  Feature Store  ──▶  Decision Engine  ──▶  Response

File				Layer				What it does
dim3_feature_store.txt		Dimension 3 — data serving	Hot/warm/cold in-memory store. Hot path refreshed every 15 min. Warm path updated per lender event. Cold path refreshed by daily batch. get_store_health correctly reports freshest_write=max(written_ats), oldest_write=min(written_ats).
dim3_eligibility_api.txt	Dimension 3 — API		check_eligibility() and check_eligibility_batch(). Reads from feature store, runs decision engine, returns external-safe EligibilityResponse within 200ms p99. stale_path_threshold_minutes=15 aligns with HOT_PATH_MAX_AGE_MINUTES.
qa_api_output_contract.txt	QA on API + state outputs	12 Python checks: EligibilityResponse field validity (7 checks including NO_DATA/nonzero-limit and latency SLA), state transition output validity (5 checks including persistence-block-without-prior-state)

Orchestration

File			Role
orchestrator.txt	Full batch DAG with dependency ordering (vw1→…→vw6→decision engine→layers 5-8→feature store→outcome tracking). Cross-cycle state persistence: previous_capacity_df (stability smoothing), prior_state_df (persistence enforcement), circuit_breaker_multiplier (portfolio feedback). QA gates between SQL and Python stages. Near-realtime lender feedback event handler that writes to warm feature path immediately.
