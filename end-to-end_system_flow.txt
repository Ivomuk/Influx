2. Decision Engine (Python, Layers 2–4)

layer1_df + layer0_df
        │
        ▼
prepare_decision_base
  Validates required columns, coerces types, inner-joins L1 + L0
        │
        ▼
build_policy_prefilter          ← Dimension 4 + 5
  Computes exposure_to_inflow_ratio, thin_file_flag, recent_disbursement_no_repayment_flag
  Anti-gaming blocks: timing_manipulation_flag, loan_cycling_flag → policy_restrict_flag
  Sets feasible_action_set per subscriber (which actions are allowed)
  Sets primary_policy_reason (first matching reason code)
        │
        ▼
evaluate_tnv_actions
  For each subscriber × each feasible action:
    Expected TNV = Immediate Margin
                 + Discounted Future Transaction Margin
                 − Expected Credit Loss
                 − Expected Churn Cost
                 − Expected Treatment Cost
        │
        ▼
select_final_capacity_output    ← Dimension 4
  Picks highest-TNV feasible action per subscriber
  Applies policy_capacity_cap (hard ceiling)
  Applies stability_multiplier (action-level smoothing)
  Applies stability smoothing: bounds delta from previous cycle
    (max +25% increase / max −40% decrease per run)
  Optional: network-wide budget constraint (disabled by default)
  Outputs: selected_action, CreditLimit, decision_status, prev_credit_limit


3. State, Intervention, Portfolio, Governance (Layers 5–8)

policy_prefilter_df + final_capacity_df
        │
        ▼
build_customer_state_df         ← Dimension 4
  Assigns: Healthy / At Risk / Distressed / Cooling Off / Recovered / Restricted / Fraud Review
  Persistence enforcement: blocks upward state transitions until minimum days elapsed
  Tracks state_change_dt for next cycle
        │
        ▼
build_intervention_df
  Flags: wallet_drop, rising_dsi, missed_repayment, repeat_borrowing, cooling_off, recovery
  Sets intervention_action per subscriber
        │
        ▼
build_portfolio_monitor_df      ← Dimension 4
  Computes portfolio-level: restrict_rate, distressed_rate, fraud_review_rate,
                             stacked_borrowing_rate, exposure_concentration
  Emits portfolio_control_signal:
    STABLE_PORTFOLIO → multiplier 1.00
    STACKING_CAP_TIGHTENING → 0.80
    EXPOSURE_CAP_REBALANCING → 0.75
    DISTRESS_POSTURE_TIGHTENING → 0.70
    FRAUD_PRESSURE_TIGHTENING → 0.65
    SYSTEM_WIDE_TIGHTENING → 0.60
  circuit_breaker_capacity_multiplier fed back to next decision run
        │
        ▼
build_governance_log_df
  Flags high-value and restricted subscribers for manual review
  Records persistence_block_applied, prev_credit_limit, audit_trigger_flag

5. Real-Time Eligibility API (Dimension 3, request-driven)

Lender calls check_eligibility(msisdn)
        │
        ▼
Feature Store read (hot → warm → cold, <5ms target)
  If stale (>15min): is_stale=True, still served
  If missing: return CreditLimit=0, decision_status=NO_DATA
        │
        ▼
_run_single_subscriber_decision
  Runs full Layer 2–4 engine on single subscriber's features
  If engine errors: return CreditLimit=0, decision_status=ENGINE_ERROR
        │
        ▼
EligibilityResponse (external-safe fields only)
  MSISDN, CreditLimit, validity_period_days, decision_timestamp,
  policy_version, decision_status, is_stale, latency_ms
  (no scores, states, or reason codes exposed)
  p99 latency target: <200ms


6. Outcome Tracking (Dimension 6, runs after each batch)

final_capacity_df + layer0_df + layer1_df
        │
        ▼
store_decision_snapshot
  Joins decision + all L0 scores + key L1 features into timestamped record
        │
        ▼
compute_realised_outcomes  (after outcome_lookback_days = 30)
  Joins snapshots to lender_feedback: did_repay, did_default, actual_repayment_ratio
        │
        ├──▶ compute_calibration_metrics
        │      Predicted vs actual repayment rate by probability decile
        │      Flags miscalibrated buckets (error > 0.10)
        │
        ├──▶ compute_dsi_accuracy
        │      Actual default rate per DSI band
        │      Monotonicity check: higher DSI must mean higher default rate
        │
        ├──▶ compute_fairness_metrics
        │      Restrict rate per segment (sim_age_cohort, kyc_tier, region)
        │      Disparate impact flag if segment rate > 3× system average
        │
        └──▶ generate_all_explanations
               Per-subscriber: primary_driver, counterfactual_text,
               full_text, sms_text (≤160 chars)
