2. Decision Engine (Python, Layers 2–4)

layer1_df + layer0_df + vw5_reason_codes_df + vw6_cap_action_df
                      + circuit_breaker_multiplier (from prior portfolio run)
        │
        ▼
run_credit_v1_decision_engine(circuit_breaker_multiplier)
  Scales policy_capacity_cap by multiplier before any subscriber evaluation
        │
        ▼
prepare_decision_base
  Validates required columns, coerces types, inner-joins L1 + L0
        │
        ▼
build_policy_prefilter(vw5_reason_codes_df)
  Computes exposure_to_inflow_ratio, thin_file_flag, recent_disbursement_no_repayment_flag
  Anti-gaming blocks: timing_manipulation_flag, loan_cycling_flag → policy_restrict_flag
  Sets feasible_action_set per subscriber (which actions are allowed)
  Sets primary_policy_reason from Python np.select, then overrides with vw5
  reason code where vw5 has a non-ELIGIBLE_BASELINE code (SQL audit trail wins)
        │
        ▼
evaluate_tnv_actions
  For each subscriber × each feasible action:
    Expected TNV = Immediate Margin
                 + Discounted Future Transaction Margin
                 − Expected Credit Loss
                 − Expected Churn Cost
                 − Expected Treatment Cost
        │
        ▼
select_final_capacity_output(vw6_cap_action_df)
  Picks highest-TNV feasible action per subscriber
  Applies policy_capacity_cap (hard ceiling, already scaled by circuit breaker)
  Applies stability_multiplier (action-level smoothing)
  Applies stability smoothing: bounds delta from previous cycle
    (max +25% increase / max −40% decrease per run)
  Applies vw6 conservative_credit_limit_v1 as hard per-subscriber ceiling
    (np.minimum after all other computation)
  Outputs: selected_action, CreditLimit, decision_status, prev_credit_limit

8. Orchestration (orchestrator.txt)

Wires all of the above into a single batch DAG with dependency ordering:
  vw1 → vw2 → vw3 → vw4 → vw5 → vw6
  → SQL QA gates
  → decision engine (receives vw5, vw6, circuit_breaker_multiplier)
  → Python QA gate
  → layers 5–8 (emits new circuit_breaker_multiplier)
  → feature store bootstrap
  → outcome tracking
  → external lender interface

Cross-cycle state persisted between runs:
  previous_capacity_df        — stability smoothing (max ±25%/40% delta)
  prior_state_df              — persistence enforcement (blocks early state reversal)
  circuit_breaker_multiplier  — portfolio feedback (scales policy_capacity_cap)

Near-realtime handler: handle_lender_feedback_event()
  Calls feedback pipeline then writes to warm feature store path immediately
  Ensures eligibility API sees updated exposure within 30 min of lender report
